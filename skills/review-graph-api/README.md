# review-graph-api Skill

Reviews Microsoft Graph API reference documentation changes in GitHub PRs, branches, or workspace files against documentation plans and Microsoft Graph authoring guidelines. Produces a severity-ranked review report with actionable findings organized by validation phase.

## Prerequisites

- **Microsoft Graph docs repository** cloned locally (the repo containing `api-reference/`, `changelog/`, `concepts/`)
- **Validation scripts** available: `scripts/validate-changelog-json.ps1` and `scripts/validate-temp-docstubs.ps1`
- **Documentation Plan** (recommended) — generated by the `generate-doc-plan` skill for completeness validation
- **API.md file** (recommended) — for technical accuracy validation against the API specification

## How to Invoke

Example prompts:

```
Review PR #1234 in microsoftgraph/microsoft-graph-docs
```

```
Review the changes on branch feature/new-security-apis
```

```
Review the changed files in my workspace against the documentation plan in temp-docstubs
```

```
Review PR #1234 — I've placed the documentation plan and API.md in temp-docstubs
```

## Expected Output

A structured review report containing:

1. **Gate Decision** — Approve, Request Changes, or Not Reviewable
2. **Summary** — files reviewed, issues by severity, validation script results
3. **Findings by Phase** — each finding includes file path, issue, fix, and rule reference
4. **Severity Levels:**
   - **Critical (Must Fix)** — blocks merge (missing namespace, broken links, TODO placeholders, non-alphabetical tables, validation failures)
   - **Warning (Should Fix)** — incomplete coverage (missing optional sections, partial changelog)
   - **Info (Consider)** — best practices and style improvements

## Review Phases

| Phase | What it validates |
|---|---|
| **A — Traceability Map** | Maps Documentation Plan → expected files → actual changes (requires Documentation Plan) |
| **B — Structural Integrity** | Template compliance, required sections, heading order, includes, file placement |
| **C — Completeness** | All planned files changed, all methods/resources documented, no scope creep |
| **D — Technical Accuracy** | Titles, descriptions, examples, URLs, permissions, naming conventions |
| **E — Cross-File Consistency** | Enum consistency, polymorphic types, version alignment, link integrity |
| **Validation Scripts** | Changelog JSON validation, temp-docstubs cleanup verification |

## Tips

- **Generate a documentation plan first** — use the `generate-doc-plan` skill before review for the most comprehensive validation
- **Provide API.md** — enables accuracy checks against the API specification
- **Without context files** — review is limited to guidelines compliance only (structure, formatting, naming conventions)
- **Large PRs (15+ files)** — the skill reviews in batches of 10 files, reporting findings after each batch
- **Quick checks** — the Top 13 Review Rules are checked first for every file (see `references/top-review-rules.md`)
