# Changelog Validation Rules

Validation rules for changelog files (`changelog/*.json`).

---

## JSON Structure

A changelog file has a top-level `changelog` array containing one or more records:

```json
{
  "changelog": [
    {
      "ChangeList": [ ... ],
      "Id": "{guid}",
      "Cloud": "Prod",
      "Version": "beta",
      "CreatedDateTime": "2025-01-15T10:30:00.0000000Z",
      "WorkloadArea": "Security",
      "SubArea": ""
    }
  ]
}
```

## Record-Level Properties

| Property | Required | Rules |
|---|---|---|
| `ChangeList` | Yes | Array of change items |
| `Id` | Yes | GUID — must match the `Id` in ChangeList items |
| `Cloud` | Yes | `"Prod"` for new entries; `"prd"` acceptable in older entries |
| `Version` | Yes | `"v1.0"` or `"beta"` only |
| `CreatedDateTime` | Yes | ISO 8601/RFC 3339 format with fractional seconds and Z suffix (e.g., `2025-01-15T10:30:00.0000000Z`) |
| `WorkloadArea` | Yes | Must match CDK taxonomy (e.g., "Security", "Identity and access") |
| `SubArea` | Yes | May be empty string `""` — must match CDK taxonomy if populated |

## ChangeList Item Properties

| Property | Required | Rules |
|---|---|---|
| `Id` | Yes | GUID — must match the record-level `Id` |
| `ApiChange` | Yes | Type of API artifact: "Property", "Resource", "Method", "Relationship", "Enumeration", "Member", "Permission" |
| `ChangedApiName` | Yes | Name of the changed API element |
| `ChangeType` | Yes | One of: "Addition", "Change", "Deprecation", "Deletion" |
| `Description` | Yes | Markdown description with full Learn URLs |
| `Target` | Yes | Target resource or entity name |

## GUID Consistency

- The `Id` at the record level and the `Id` in each `ChangeList` item **must be the same GUID**
- Use the GUID from the autogenerated changelog file — do not modify it

## Description URLs

- Must use full Learn URLs: `https://learn.microsoft.com/graph/api/...`
- Beta links: append `?view=graph-rest-beta&preserve-view=true`
- v1.0 links: no query string parameters
- Resource type names and property names in **bold** markdown

## New Records

- Add new records as the **first item** in the `changelog` array
- Do not insert into or modify existing records
- Copy complete records from autogenerated files (not just ChangeList items)

## Validation Script

Run after any changelog modification:

```powershell
.\scripts\validate-changelog-json.ps1
```

Validates: schema compliance, required properties, GUID consistency, date format, JSON structure.

## Common Failures

| Issue | Fix |
|---|---|
| Missing fractional seconds in `CreatedDateTime` | Use format `YYYY-MM-DDTHH:mm:ss.fffffffZ` |
| `Id` mismatch between record and ChangeList | Ensure same GUID used everywhere |
| `Cloud` value wrong | Use `"Prod"` (not "Production", "prod", etc.) |
| Malformed JSON | Check comma placement between records |
| Invalid `Version` | Only `"v1.0"` or `"beta"` |
